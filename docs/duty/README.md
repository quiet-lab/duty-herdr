# duty-herdr

Форк herdr для рабочего места duty. Ветвь `master` зеркалит upstream
`herdrdev/herdr` (только fast-forward), ветвь `duty` — `master` с патчами
форка. Версия в `Cargo.toml` остаётся upstream'ной, признак форка —
`HERDR_BUILD_ID` (тег выпуска): `herdr --version` печатает
`herdr 0.9.5 (duty-v0.9.5.1 ee5bfb5)` для выпуска (тег и семь знаков
коммита) и `herdr 0.9.5 (dev)` для сборки без `HERDR_BUILD_ID`.
Документы upstream (`docs/next/**`, `docs/preview/**`, `docs/versions/**`)
не правятся; описание форка ведётся только здесь.

## Что меняет форк

- Значки состояния агентов: таблица `[ui.status_icons]` переопределяет
  значок каждого состояния поверх `status_indicators`.
- Форма курсора по экрану агента: таблица `[ui.cursor_shape_by_screen]`
  выбирает форму курсора панели по тексту нижнего буфера распознанного
  агента.
- Токен `focused_tab` в строках агентов: подпись вкладки, выбранной
  в workspace агента.
- `agent prompt`: Enter отправляется после того, как текст появился
  на экране агента; текст не появился — одна повторная вставка, затем
  ошибка `agent_prompt_lost`.
- Обновление: `herdr update` и удалённая установка берут манифест
  `latest.json` из Releases форка `quiet-lab/duty-herdr`; установка
  из пакета pacman распознаётся, `herdr update` печатает подсказку
  обновить пакет.
- Установка: `distribution/install.sh` ставит выпуск форка.
- Подписи spaces и вкладок: символ, место и приложение вместо ручной
  подписи; таблица `[ui.workspace_symbols]` задаёт символы и цвета
  по каталогам.
- Оформление строк sidebar по фокусу вкладки: фон токена `bg`, цвет
  `$panel` и условие правила `active`.
- Дерево workspace: явная связь «родитель → дочерний» как факт сервера,
  показ дочерних под родителем в панели Spaces, перемещение блоком
  из CLI и клавишами.
- Выпускается только `linux-x86_64`; канал `preview` не публикуется.

## Настройка

Значки состояния. Значки задают пять ключей: `idle`, `working`, `blocked`,
`done`, `unknown`. Значение — непустая строка шириной 1–2 ячейки без
селектора вариации U+FE0F либо непустой массив таких строк одной ширины;
иное значение отклоняет разбор конфигурации. Незаданное состояние берёт
значок из `status_indicators`.

```toml
[ui.status_icons]
idle = "🟡"
working = "🟢"
blocked = "🔴"
done = "✅"
unknown = "·"
```

Вариант с символами:

```toml
[ui.status_icons]
idle = "○"
working = "●"
blocked = "◆"
done = "✓"
```

Массив задаёт кадры анимации: клиент показывает их по кругу. Период кадра
задаёт `frame_interval_ms` — миллисекунды, целое от 50 до 5000 (иное значение
отклоняет разбор). Значение — число для всех состояний или таблица
`{ working = 83, blocked = 333 }` с ключами `idle`, `working`, `blocked`,
`done`, `unknown` (неизвестный ключ отклоняет разбор; пропущенное состояние —
400). Кадр — функция монотонных часов клиента и часов строки, поэтому по
умолчанию все строки одного состояния показывают один кадр. Кадры — состояние
показа: сервер, API и протокол о них не знают.

Ключ `frame_phase` (`"synced"` по умолчанию или `"per_row"`; иное значение
отклоняет разбор) разводит строки одного состояния. В режиме `per_row` строка
стартует со сдвигом по времени: кадр строки —
`((прошедшее время + сдвиг) / период) % число кадров`, сдвиг лежит равномерно
в отрезке от нуля до `период × число кадров` и берётся из детерминированного
хеша идентификатора строки: workspace (`w4`) для панели Spaces, панели
(`w4:p1`) для панели агентов; в виде нескольких машин в хеш входит и
идентификатор машины. Граница кадра строки лежит на `k × период − сдвиг`, поэтому
промежутки между её сменами кадра равны. Сводные значки без строки (счётчики
в мобильной шапке) идут от начала отсчёта с периодом состояния. Сдвиг не меняется
между перезапусками клиента. Режим действует на все анимированные состояния.

Ключ `frame_speed_spread` (число от 0.0 до 0.5, по умолчанию 0.0; иное
значение отклоняет разбор) в режиме `per_row` даёт строке ещё и свой период:
период состояния умножается на множитель из того же хеша, равномерно из
отрезка от `1 − разброс` до `1 + разброс`. Значение — число для всех состояний
или таблица `{ working = 0.25, blocked = 0.0 }` с ключами `idle`, `working`,
`blocked`, `done`, `unknown` (неизвестный ключ отклоняет разбор; пропущенное
состояние — 0.0). Сдвиг старта общий для всех состояний, разброс скорости — свой
у каждого. При `synced` или нулевом разбросе множитель равен 1.

Такт идёт по границам кадров: срок таймера цикла клиента ставится на ближайшую
будущую границу среди строк в анимированном состоянии, поэтому каждая строка
меняет кадр в свой момент. Границы в одном окне 2 мс объединяются в один такт.
Частота тактов растёт с числом анимированных строк (у десяти строк по 12 кадров
в секунду — до 120 тактов в секунду без совпадений); перерисовка такта
использует сохранённую поверхность панелей и не зависит от числа панелей.

```toml
[ui.status_icons]
working = ["🌑", "🌒", "🌓", "🌔", "🌕", "🌖", "🌗", "🌘"]
idle = "☕"
blocked = ["📣", "🔔"]
done = "✅"
unknown = "🗿"
frame_interval_ms = { working = 83, blocked = 333 }
frame_phase = "per_row"
frame_speed_spread = { working = 0.10 }
```

Смена кадра идёт по времени: это исключение из запрета таймеров, источника
событий у анимации нет. Срок берётся из существующего таймера цикла клиента
и ставится, только пока в снимках показанных конечных точек есть строка
в анимированном состоянии, в том числе строка вне экрана или без значка: такая
строка стоит перерисовки без видимых изменений. Пока нет согласованной
поверхности панелей (например, при изменении размера окна), кадр не меняется.
Условие снятия — отказ от анимированных значков.

Свёрнутая панель в режиме `compact` оставляет значку одну ячейку: значок
шириной две ячейки в ней не показывается, а период при этом продолжает идти;
для неё годятся кадры шириной в одну ячейку.

Цвет токена из метаданных. Поле `fg` стиля токена и правила `rules`
принимает, кроме `#hex`, ссылку `"$<имя>"` на пользовательский токен
текущего элемента: для панели spaces это токены workspace, для панели
агентов — токены панели. Имя проверяется как у пользовательских токенов
`$name` в `rows` (до 32 символов: буквы ASCII, цифры, `_`, `-`). Значение
токена разбирается как `#RGB` или `#RRGGBB`; токена нет, он пуст или не
цвет — ссылка не действует, берётся `fg` более общего уровня либо цвет
темы. Сравнение значений в `rules` не меняется. Цвет относится к тексту
токена, не к фону строки.

```toml
[ui.sidebar.spaces]
rows = [
  ["state_icon", { token = "workspace", fg = "$color" }],
  ["branch", "git_status"],
]
```

Цвет задают командой, источник и значение меняются на лету:

```sh
herdr workspace report-metadata <ws> --source duty --token color=#f9e2af
herdr pane report-metadata <pane> --source duty --token color=#f9e2af
```

Главной сессии репозитория выдаётся белый цвет: `color=#ffffff`.

Токен `focused_tab` — подпись вкладки, выбранной в workspace агента,
с учётом выбора этого клиента. В отличие от `tab`, показывается всегда,
а не только при нескольких вкладках или заданной подписи. Это текстовый
токен: принимает `fg`, `bold`, `dim` и `rules` так же, как `tab`.
Раскладка строк агентов:

```toml
[ui.sidebar.agents]
rows = [["state_icon", "machine", "tab"], ["focused_tab"], ["agent"]]
```

Команда `agent prompt` на Linux и macOS отправляет Enter, когда на экране
агента появился хвост текста (последние 24 графемы без пробелов и
символов рамок) или метка свёрнутой вставки (`[Pasted text #…`,
`[Pasted Content …`). Ожидание одной попытки — 5 с; затем текст
вставляется ещё раз, и после второй неудачи команда возвращает ошибку
`agent_prompt_lost`, а Enter не отправляется. На Windows остаётся
пауза 300 мс между текстом и Enter.

Если эхо первой попытки приходит после повтора в одном кадре с ним, текст
на экране оказывается дважды: Enter не отправляется, команда возвращает
`agent_prompt_lost` с пояснением об удвоении. Эхо первой попытки,
нарисованное отдельно раньше эха повтора, от него не отличить. Пока
отправка ждёт эха, ввод пользователя в панель (в том числе Ctrl-C)
проходит сразу; экран проверяется только по изменению содержимого и только
по нижним 12 строкам.

Форма курсора по экрану агента. Таблица `[ui.cursor_shape_by_screen.<агент>]`
задаёт форму курсора панели, в которой распознан этот агент. Ключ —
канонический идентификатор агента (поле `agent` в `herdr agent list`);
другой ключ отклоняет разбор секции `[ui]`.

```toml
[ui.cursor_shape_by_screen.claude]
default = "steady_block"
rules = [
  { contains = "-- INSERT --", shape = "steady_bar", bottom_non_empty_lines = 2 },
]
```

Текст проверяется в том же снимке нижнего буфера, что у распознавания
состояния агента, а не в видимой области панели. Правила проверяются
по порядку, первое совпадение даёт форму; нет совпадения — `default`; нет
`default` — форма панели не трогается. Поля правила:

- `contains` — непустая подстрока одной строки экрана, регулярных выражений
  нет;
- `shape` — `block`, `steady_block`, `underline`, `steady_underline`, `bar`,
  `steady_bar`, как у `cjk_ime_cursor_shape`;
- `bottom_non_empty_lines` — необязательное число больше нуля: искать только
  в стольких нижних непустых строках. Без него поиск идёт по всему экрану,
  и текст разговора с той же подстрокой тоже даёт совпадение. Счёт идёт
  по рядам экрана: в узкой панели перенесённая строка статуса занимает
  несколько рядов, а подстрока, разорванная переносом, не находится.

Форма правила главнее собственного DECSCUSR программы, пока правило
действует. Нет совпадения и нет `default`, агент завершился, панель сменила
программу — возвращается собственная форма панели. Экран проверяется при
каждом изменении вывода панели, кроме незакрытого кадра синхронного вывода,
и только у панелей, агент которых есть в таблице. `herdr server reload-config`
применяет новые правила сразу, без вывода в панели. Включённый
`reveal_hidden_cursor_for_cjk_ime` главнее правил: он задаёт видимому курсору
форму `cjk_ime_cursor_shape`.

Claude Code показывает курсор терминала только с переменной окружения
`CLAUDE_CODE_NATIVE_CURSOR=1`; без неё он рисует свой блок поверх курсора,
и форма правила не видна. Подпись режима `-- INSERT --` Claude Code выводит
в последней строке экрана только в режиме редактора vim; подписи
`-- NORMAL --` нет, поэтому блок задан через `default`.

### Подписи spaces и вкладок

Ручная подпись workspace или вкладки показывается, только пока в них
определён агент (у workspace — в первой вкладке); иначе показывается
автоматическая подпись `auto_label` — «<символ> <место> · <приложение>»
без отсутствующих частей. Правило общее для строки spaces, полосы вкладок,
токенов `tab` и `focused_tab` панели агентов, мобильного вида и токенов
`{workspace}` и `{tab}` заголовка окна `ui.window_title`.

Токены строки spaces (`ui.sidebar.spaces.rows`):

- `symbol` — символ workspace;
- `place` — имя репозитория корневой панели первой вкладки, вне git —
  путь с `~`;
- `app` — агент первой вкладки, пока он определён, иначе процесс
  переднего плана сфокусированной панели первой вкладки;
- `auto_label` — «<символ> <место> · <приложение>»;
- `workspace` — ручная подпись, пока в первой вкладке определён агент,
  иначе `auto_label`.

Когда активна не первая вкладка, под строкой workspace идёт строка этой
вкладки с префиксом `   └─ `. Подпись вкладки — ручная при живом агенте
в ней, иначе `auto_label` вкладки с символом workspace.

```toml
[ui.sidebar.spaces]
rows = [["state_icon", "symbol", "place", "app"], ["branch", "git_status"]]
```

Символы и цвета задаёт таблица `[ui.workspace_symbols]`. Значение символа
проверяется как у `ui.status_icons`; плохое значение отклоняет всю секцию
`[ui]`.

```toml
[[ui.workspace_symbols.dirs]]
path = "~/work/pets/duty-herdr"   # обязателен: абсолютный путь или с ~
main = "🦁"                        # символ корневого workspace
tasks = ["🦄", "🦌", "🦊", "🦇"]   # символы дочерних, по умолчанию []

[ui.workspace_symbols.outside]    # необязателен: каталоги вне dirs
main = "🏠"
tasks = ["🐟"]

[ui.workspace_symbols.color_rule] # необязателен; значения по умолчанию
hue_step = 10                     # шаг оттенка, градусы, делитель 360
saturation = [50, 70]             # насыщенность, проценты: [min, max]
value = [70, 100]                 # яркость (value), проценты: [min, max]
```

Поле `colors` убрано: в `dirs` и `outside` оно отклоняет секцию `[ui]`
с сообщением «colors is no longer supported: the color is computed by the
rule ui.workspace_symbols.color_rule».

Каталог workspace — корень git корневой панели первой вкладки, без git —
её cwd. Выбирается запись `dirs` с самым длинным совпавшим префиксом
по компонентам пути, при равенстве — первая; нет совпадения — `outside`;
нет `outside` — символа и цвета нет. Корневой workspace получает токен
`symbol` со значением `main` (вычисляется по текущему каталогу), без цвета.
Дочерний (`create --parent`, `set-parent`) получает первый свободный
символ из `tasks` записи родителя (занятые — итоговые `symbol` открытых
workspace, включая токены `duty`) и случайный цвет по `color_rule`:
оттенок — одно из `360 / hue_step` значений, не занятое итоговым `color`
других открытых workspace (оттенок занятого цвета округляется к ближайшему
шагу; заняты все — любой), насыщенность и яркость — случайные непрерывные
значения из диапазонов, результат `#rrggbb`. Символы исчерпаны — символа нет. Пара
закрепляется и сохраняется в снимке сессии. `set-parent` на другого
родителя выдаёт свободную пару из записи нового родителя (своя прежняя
пара занятой не считается), на того же — пару не меняет, `--clear`
возвращает символ `main`. Дочерний из снимка сессии без закреплённой пары
получает её при восстановлении, после восстановления всех workspace,
в порядке их номеров. Цвет доступен токеном
метаданных `color`, например `{ token = "place", fg = "$color" }`.

Токены `report-metadata` внешнего источника главнее токенов herdr по каждому
ключу; снятый внешний токен возвращает значение herdr:

```sh
herdr workspace report-metadata <ws> --source duty --token symbol=🥑
```

Поле `foreground_process` в выводе `herdr pane list` и `herdr pane get` —
процесс переднего плана панели; при отсутствии значения поле опускается.

### Оформление строк по фокусу вкладки

Стиль токена в `ui.sidebar.agents.rows` и `ui.sidebar.spaces.rows`
принимает фон `bg` наравне с `fg`, в общем стиле и в правилах. Значения
цвета:

- `#RGB`, `#RRGGBB`;
- `$имя` — цвет из значения токена метаданных; в строках агентов токен
  ищется у панели, затем у её workspace;
- `$panel` — фон панели sidebar текущей темы. В `bg` строка остаётся
  на фоне панели вместе с подсветкой строки темы (фокус). В `fg` — фон
  sidebar темы (`sidebar_bg`), а если тема оставляет фон терминала —
  фон терминала, о котором он сообщил, иначе `panel_bg` темы. Имя
  `panel` зарезервировано: токен метаданных `panel` цветом не служит.

Первый токен строки с фоном (`#…` или `$имя`) заливает строку на всю
ширину панели вместе с разделителями и отступом. Под курсором навигации
и при перетаскивании workspace фон курсора главнее: заливка не рисуется,
текст с `fg = "$panel"` берёт цвет фона своего токена.

Условие правила `active = true|false` — вкладка активна в своём
workspace; условие одно на правило, как `equals` и прочие, `ignore_case`
к нему не применяется, `hide` работает так же. Совпадает:

- в строках агентов — у `tab` (вкладка агента) и `focused_tab` (всегда
  активна);
- в строках spaces — у `workspace`, `place`, `app`, `auto_label`
  (заголовок workspace описывает первую вкладку) и у строки активной
  не первой вкладки (активна всегда; стиль — первого из токенов
  `workspace`, `place`, `auto_label` первой строки).

У остальных токенов условие не совпадает.

Значение цвета `fg` и `bg` принимает до трёх вариантов через `|`
(`"$color|#ffffff"`, `"$accent|$color|#89b4fa"`): берётся первый, который
раскрывается. Токен раскрывается, если он есть и его значение — цвет
`#RGB` или `#RRGGBB`; `$panel` и литерал раскрываются всегда. Пустой
вариант, неизвестное имя переменной, плохой литерал, пробелы вокруг `|`
и вариант после `$panel` или литерала (он недостижим) отвергаются при
чтении конфигурации. Workspace без токена `color` с запасным `#ffffff`
остаётся читаемым.

Выбранная вкладка — на фоне панели цветом подписи workspace, остальные —
наоборот (inline-таблица TOML пишется в одну строку, переносы допустимы
внутри массива):

```toml
[ui.sidebar.agents]
rows = [[
  "state_icon",
  { token = "tab", fg = "$panel", bg = "$color|#ffffff", rules = [{ active = true, fg = "$color|#ffffff", bg = "$panel" }] },
]]

[ui.sidebar.spaces]
rows = [[
  "state_icon",
  { token = "workspace", fg = "$color|#ffffff" },
]]
```

#### Полоса вкладок

Вкладки выбранного workspace красятся ключами `active` (вкладка в фокусе)
и `inactive` (остальные) таблицы `[ui.tab_bar]`. Стиль — тот же, что
у токена sidebar: `fg`, `bg`, `bold`, `dim`; цвет — `#RGB`, `#RRGGBB`,
`$panel` (фон панели, `palette.panel_bg`), `$имя` и запасные варианты
через `|`. Токен `$имя` берётся у workspace вкладки. Ключ не задан или
цвет не раскрылся — действует цвет темы, поэтому без `[ui.tab_bar]`
вид не меняется. Стрелки прокрутки, разделители и правые записи полосы
остаются цветами темы; `bold = false` снимает и жирность вкладки с заданным именем. Выбранная вкладка — цветом подписи workspace
на фоне панели, остальные — наоборот:

```toml
[ui.tab_bar]
active = { fg = "$color|#ffffff", bg = "$panel" }
inactive = { fg = "$panel", bg = "$color|#ffffff" }
```

## Дерево workspace

Workspace хранит необязательное поле `parent_workspace_id`: оно отдаётся
в `WorkspaceInfo`, снимке клиента и событиях `workspace.created`,
`workspace.updated`, сохраняется в снимке сессии. Вложенность одна.

```sh
herdr workspace create --parent <ws> [--cwd <путь>] [--label <имя>]
herdr workspace set-parent <ws> --parent <родитель>
herdr workspace set-parent <ws> --clear
herdr workspace move <ws> --before <цель>
herdr workspace move <ws> --after <цель>
herdr workspace move <ws> --index <N>
```

`create --parent` вызывает метод `workspace.create_child`: это параметры
`workspace.create` и обязательный `parent_workspace_id`. Метод
`workspace.create` замороженного контракта клиента не меняется, старый сервер
отвечает ошибкой о неизвестном методе, а не игнорирует родителя. Снятие связи
в API — `workspace.set_parent` с `parent_workspace_id: null`.

Коды отказа `workspace.set_parent` и `workspace.create_child`:

| Код | Причина |
|---|---|
| `workspace_not_found` | workspace или родитель не существует |
| `workspace_parent_self` | ссылка на себя |
| `workspace_parent_nested` | у родителя есть свой родитель, у дочернего есть свои дочерние (в том числе цикл) |
| `workspace_parent_worktree_child` | дочерний или родитель — linked-дочерний worktree-группы |
| `workspace_parent_worktree_group` | дочерний — корень worktree-группы |

Закрытие родителя не закрывает дочерние и не требует `--group`: они становятся
корневыми, о каждом приходит `workspace.updated`. Связь снимается так же, когда
дочерний становится корнем worktree-группы, и при восстановлении сессии, если
родителя нет.

Панель показывает дочерних сразу под родителем с отступом, в порядке
`state.workspaces`. У корня worktree-группы сначала идут linked-дочерние, затем
явные. Группа сворачивается как worktree-группа, свёрнутая показывает только
дочерний в фокусе. Перетаскивание мышью переносит родителя блоком, дочерний
не перетаскивается.

`workspace move` и клавиши работают на уровне записи: корень идёт вместе со
своей группой среди корней, дочерний — среди дочерних того же родителя. Цель
`--before` и `--after` — запись того же уровня; `--index` считается с нуля среди
записей уровня. Запись уже на месте — порядок не меняется, команда печатает
текущий список.

Действия клавиш без привязки по умолчанию, раздел `[keys]`:

```toml
[keys]
move_workspace_up = "prefix+alt+up"
move_workspace_down = "prefix+alt+down"
```

## Установка и обновление

Установщик одной командой:

```sh
curl -fsSL https://raw.githubusercontent.com/quiet-lab/duty-herdr/duty/distribution/install.sh | sh
```

Репозиторий pacman на Releases форка. Строки для `/etc/pacman.conf`:

```ini
[duty-herdr]
SigLevel = Optional TrustAll
Server = https://github.com/quiet-lab/duty-herdr/releases/latest/download
```

Установка пакета:

```sh
paru -S duty-herdr-bin
```

Пакет `duty-herdr-bin` объявляет `provides=(herdr)` и
`conflicts=(herdr herdr-bin)`: пакеты `herdr` и `herdr-bin` перед
установкой удаляются. Бинарник ставится в `/usr/bin/herdr`. Пакет собирается из шаблона
`packaging/arch/duty-herdr-bin/PKGBUILD`.

Установщик читает `releases/latest/download/latest.json`, проверяет
SHA-256 и ставит бинарник в каталог установки. Платформа — только
Linux x86_64; на других установщик завершается ошибкой.

Обновление — `herdr update`. Манифест берётся по адресу
`https://github.com/quiet-lab/duty-herdr/releases/latest/download/latest.json`;
обновление ставится при большей версии либо при той же версии с другим
`build_id` (сборка без `HERDR_BUILD_ID` отличается от любого выпуска).
Канал `preview` отклоняется с подсказкой `herdr channel set stable`.
Установка из пакета pacman (`/usr/bin/herdr` числится в
`/var/lib/pacman/local/duty-herdr-bin-*`) не обновляется самой
программой: `herdr update` печатает `paru -Syu duty-herdr-bin`.

Удалённая установка (`herdr` на SSH-хосте) берёт тот же манифест и ставит
только `linux-x86_64`; для другой платформы нужна переменная
`HERDR_REMOTE_BINARY=<путь к бинарнику>`.

## Выпуск

Выпуск собирается на станции и заливается сценарием
`scripts/release-local.sh`. Ветвь `duty` должна быть чистой, тег
не должен существовать, `gh` — авторизован, `ZIG` — задан.

```sh
just release-local duty-v0.9.5
just release-local duty-v0.9.5 --dry-run
just release-local duty-v0.9.5.1 --install --notes-file заметки.md
```

Тег — `duty-v<версия Cargo.toml>`; повторный выпуск той же версии —
`duty-v<версия Cargo.toml>.N`; иной тег сценарий отклоняет. Сценарий выполняет по порядку:

1. `cargo fmt --check`, `cargo clippy --all-targets`, `just test`
   (`just check` не годится: требует Windows SDK);
2. `cargo build --release --locked` с `HERDR_BUILD_ID=<тег>` и
   `HERDR_BUILD_COMMIT=<sha>`;
3. `latest.json` (поле `build_id` равно тегу, `protocol` из
   `src/protocol/wire.rs`, `endpoint_generation` из
   `distribution/latest.json`);
4. пакет `duty-herdr-bin` через `makepkg` в `.local/release/<тег>/`;
5. репозиторий pacman: `repo-add`, `duty-herdr.db` и `duty-herdr.files`
   копиями обычными файлами;
6. `gh release create <тег> --target <sha>` со всеми активами:
   `herdr-linux-x86_64`, `latest.json`, пакет
   `duty-herdr-bin-<pkgver>-1-x86_64.pkg.tar.zst`, `duty-herdr.db`,
   `duty-herdr.db.tar.gz`, `duty-herdr.files`,
   `duty-herdr.files.tar.gz`; тег в origin создаёт сам `gh`, затем
   сценарий забирает его командой `git fetch`. При сбое выпуск и тег
   удаляются, повтор того же тега проходит;
7. только после успешного выпуска — `--install`.

Ключи: `--install` после успешного выпуска ставит собранный бинарник в `~/.local/bin/herdr`,
`--dry-run` печатает шаги без сборки и публикации (провал проверок
становится предупреждением), `--notes-file` задаёт заметки выпуска (без
него — `git log` от прошлого тега `duty-v*`). Окружение: `ZIG`,
необязательно `CARGO_BUILD_JOBS`. GitHub Actions форка не используются.

## Слияние upstream

1. `git fetch upstream`, затем в ветви `master`:
   `git merge --ff-only upstream/master`.
2. В ветви `duty`: `git merge v0.9.x` (тег upstream), разрешение
   конфликтов в пользу сохранения патчей форка.
3. `just test`, `cargo clippy --all-targets`, `cargo fmt --check`.
4. Выпуск: `just release-local duty-v0.9.x` — сценарий создаёт тег форка.

## Сборка на станции

Для vendored libghostty-vt нужен Zig 0.16.0; он ставится через mise:

```sh
mise use -g zig@0.16.0
export ZIG="$HOME/.local/share/mise/installs/zig/0.16.0/zig"
export CARGO_BUILD_JOBS=16
cargo build --release --locked
```

Без `ZIG` сборка завершается ошибкой. Первая сборка занимает около
трёх минут на 16 потоках.
